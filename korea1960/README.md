# 대한민국 1960: 선택의 연대기

1960년 1월 1일부터 1979년 12월 31일까지 시간이 하루씩 흐르는(한 틱 = 하루) 한국어 역사 정치·경제 시뮬레이션입니다. 국정 지표는 매달 말일에 결산합니다(240번). 플레이어는 박정희라는 역사적 출발점에서 시작하지만 1960년에는 대통령 권한이 없습니다. 관찰·사전 준비 → 1961년 통치 경로 분기(헌정/군정) → 1963년 가상 선거와 취임 → 국정 운영 → 정기 선거 또는 권력 집중의 비용 → 권한 이양·위기·1979년 평가로 이어집니다.

실제 역사는 출처와 함께 구분해 보여 주고, 모든 수치·선택 결과·가상 선거·자문위원은 창작입니다. 참조 게임의 코드·화면·대사·수치·이미지를 쓰지 않았습니다. 외부 AI API·로그인·서버·유료 서비스 없이 오프라인으로 실행됩니다.

현재 상태와 다음 작업은 **[CHECKPOINT.md](CHECKPOINT.md)**, 실제로 수행한 검증은 **[QA_REPORT.md](QA_REPORT.md)**에 있습니다.

## 실행 방법

| 방법 | 하는 일 |
| --- | --- |
| `KOREA1960.html` 더블클릭 | 설치 없이 바로 실행. 콘텐츠·삽화·글꼴이 모두 들어 있는 단일 파일(약 2.4MB). Windows는 `START_WINDOWS.bat`도 가능 |
| 웹 주소 | https://dongjin100621-sketch.github.io/-/korea1960/ (저장소의 `docs/korea1960/index.html`, 위와 같은 파일) |
| `python3 tools/serve.py` | 분리 소스(`game/`)를 127.0.0.1에서 실행. 개발할 때 사용. `--reference`는 v1 참조 구현 |
| Claude 아티팩트 링크 | `npm run build:artifact`로 만든 `dist/KOREA1960_artifact.html`을 게시한 판. 그 보기 화면은 파일 다운로드를 막으므로 ‘저장’이 **저장 텍스트 복사** 창으로 열립니다. 진행은 그 링크의 브라우저 저장소에 자동 저장됩니다 |

진행은 브라우저(localStorage)에 매 행동마다 자동 저장됩니다. 다른 기기로 옮기려면 기록실 → **저장 파일 내보내기**(JSON) → 다른 기기에서 **저장 파일 불러오기**. 파일을 받을 수 없는 환경에서는 **저장 텍스트 복사** → **저장 텍스트 붙여넣기**로 같은 일을 합니다(내용은 저장 파일과 같은 JSON). 검토용 저장 파일은 `game/saves/`에 있습니다.

## 시간

* 위쪽 시계의 **진행**(스페이스)으로 시간을 흐르게 하고 다시 누르면 멈춥니다. 배속 ×1(하루 0.7초)·×2·×4·×8, 숫자 키 1~4. 휴대폰은 아래 막대의 ▶·×n 버튼.
* 매달 1일에 사건이 오면 시계가 스스로 멈추고(‘결정 대기’), 결정하면 다시 흐릅니다. 확인 창 등 창이 열려 있거나 다른 탭에 있으면 시간이 기다립니다.
* 행동은 그 달 안 언제든 할 수 있습니다. 행동점수 3은 매달 1일에 다시 채워지고 이월되지 않습니다. 법안·공사 진행 막대와 ‘표결까지 N일’은 날마다 바뀝니다.
* 말일 다음 날 월 결산이 일어나고, 오른쪽 ‘이번 달 업무’에 ‘결산 보기’가 생깁니다. **건너뛰기**(⏭)는 그 달 남은 날을 넘겨 바로 결산하고 결산 창을 엽니다.
* 계산은 그대로 월 단위입니다. 날짜는 실제 달력(윤년 포함)을 따르며, 하루가 지날 때 바뀌는 것은 날짜뿐이고 국정 지표는 말일 결산에서만 움직입니다. 자세히: `docs/SIMULATION_RULES.md` "하루 단위 시계".

## 게임의 한 달

1. **사건 결정** — 상황판의 사건 문서에서 선택지 하나를 고릅니다. 선택지마다 국고 비용, 지표의 결정 전→후 값, 지지·관계 변화, 지연 효과(몇 개월 뒤 어떤 효과), 선거 확률, 엔딩 여부를 미리 보여 줍니다. 역사 앵커는 ‘실제 역사(출처)’와 ‘이 캠페인에서는(가상)’을 나눠 보여 주고, 후자는 지금까지의 경로에 따라 달라집니다.
2. **행동점수 3** — 정책 시행·법안 발의·사업 착수·외교·자문 임명/해임·부채 상환·사전 준비에 1점씩. 비용을 쓰는 행동은 확인 창에서 비용, 즉시 효과, 매월 효과, 월 수지 변화, 준공·표결 시점을 확인한 뒤 확정합니다. 할 수 없는 버튼에는 사유가 붙습니다. 예산 배분 수정은 무료입니다.
3. **말일 결산** — 시간이 말일을 지나면(또는 건너뛰기를 누르면) 결산합니다. 결산 창에서 재정 내역, 준공·표결·지연 효과·선거, 지표마다 원인별 기여(누르면 펼침), 지지 변화, 다음 달 사건을 보여 줍니다.

화면 배치: **한가운데는 권역 지도**입니다(시작 화면). 권역을 개발도·농업 잠재력·사업 슬롯 사용으로 칠하고, 권역 이름표 아래에 사업 표식(◇ 운영 중, ◯ 공사 중·테두리가 공정)을 둡니다. 권역을 누르거나 키보드 Enter로 고르면 권역 정보와 ‘이 권역의 사업 보기’가 열립니다. 마우스로 끌어 이동하고 휠이나 +/− 버튼으로 확대합니다. 매달 1일의 사건 문서는 지도 위에 펼쳐지며 접을 수 있습니다. 위쪽 막대에 엔딩 평가의 네 축(권리·성장·생활·환경)과 재정 지표, 날짜와 시계. 왼쪽 메뉴는 국정(지도·상황판·정책·의회)·경제·지역(재정·사업·권역)·대외·인사(외교·내각 자문)·기록(기록실)으로 묶었습니다. 오른쪽 ‘이번 달 업무’는 결정할 사건, 남은 행동점수, 이달 말 표결·준공·선거, 지난달 결산, 진행 중인 법안·사업을 보여 주고, 아래 막대에 최근 연대기가 지나갑니다. 좁은 화면에서는 업무가 본문 아래로, 시계는 아래 행동 막대로 옮겨 갑니다. 지표 버튼을 누르면 계산 규칙과 지난달 원인을 봅니다.

## 데이터를 고치는 곳

* **콘텐츠(사건·정책·사업·권역·외교·자문·엔딩·출처·지표)**: `data/game.json`만 고칩니다. 그다음 `python3 tools/validate_content.py --sync`로 분리본을 다시 만들고 ID·참조·조건·무료 선택지·이미지를 검사합니다.
* **사건의 경로별 설명**: 사건의 `context` 배열. `{conditions:[...], text}` 중 조건이 맞는 첫 항목이 ‘이 캠페인에서는’ 상자에 나옵니다. 조건 문법은 `docs/DATA_CONTRACT.md`.
* **밸런스 수치**: `data/game.json`의 `balance` 블록(체감 시작점, 가상 사건 보너스 배율, 높아진 기대, 기본 성장률, 군정·권력 집중 비용). 코드를 고치지 않고 조정할 수 있습니다. 바꾼 뒤 `npm run simulate`로 전략 8개의 엔딩 분포를 다시 재세요. 블록을 지우면 1.1.0 계산으로 돌아갑니다. 설명은 `docs/SIMULATION_RULES.md` "데이터 1.2.0 밸런스".
* **규칙·수식**: `game/engine.mjs` (문서는 `docs/SIMULATION_RULES.md`를 함께 고침). 화면에서 쓰는 설명 문구는 `game/app.mjs` 위쪽의 `METRIC_HELP`, `PHASE`.
* **ID는 바꾸지 않습니다.** 저장 파일이 ID로 상태를 복원합니다. 표시 문구만 고치면 저장 호환이 유지됩니다. 지표의 의미·사건 분기·상태 구조를 바꾸면 `meta.version`이나 `SAVE_VERSION`을 올리고 `migrateSave`에 변환을 추가합니다.
* 고친 뒤: `npm test` → `python3 tools/build_standalone.py --pages` → (글자가 새로 생겼으면) `tools/subset_font.py` → 다시 빌드.

## 저장 호환성

* 현재 저장 형식 **3**(날짜 `day` 포함), 데이터 버전 **1.2.0**. 파일은 JSON(`format: "KOREA1960_SAVE"`)이며 2MB 이하만 받습니다.
* **형식 2(게임 2.0~2.1) 저장은 그 달 1일로 변환해 불러옵니다.** 데이터 1.1.0에서 만든 저장도 마찬가지입니다. 상태 구조와 ID가 같아서 진행이 이어지고, 불러온 다음 달부터 1.2.0 밸런스 규칙으로 계산됩니다. 이미 쌓인 지표 값은 바꾸지 않습니다.
* **버전 1(제작 패키지 v1, 데이터 1.0.0) 저장은 불러올 때 자동 변환**됩니다. 브라우저에 남은 v1 자동 저장도 처음 열 때 옮깁니다. 콘텐츠 ID·수치가 같아서 진행·난수·법안·사업·지연 효과가 그대로 이어집니다.
* 그 밖의 버전, 등록되지 않은 데이터 버전(예: 1.1.1), 다른 데이터 버전의 버전 1, 다른 게임, 미등록 ID, 범위 밖 수치, 잘못된 자료형, 허용되지 않은 결산 필드는 **전부 거부**하고 현재 진행을 바꾸지 않습니다. 텍스트는 화면에서 HTML 이스케이프됩니다. 서명된 저장이 아니므로 치트 방지는 보장하지 않습니다.
* v2 저장은 v1 참조 구현에서 열 수 없습니다(버전 검사).

## 명령

```
npm test                          # 엔진 테스트 88개 (원본 28 + v2 60), 약 50초
CAMPAIGN_SEEDS=100 npm run test:game   # 자동 캠페인을 전략마다 100개로 늘린 확장 검사
npm run validate                  # 콘텐츠 검증   (python3 tools/validate_content.py)
npm run simulate                  # 전략 8개의 엔딩 분포·최종 지표 평균 (node tools/simulate.mjs 40)
npm run build                     # KOREA1960.html 빌드
npm run build:pages               # 빌드 + docs/korea1960/index.html 복사
npm run test:browser              # 브라우저 검수 (Playwright 필요)
npm run test:artifact             # 웹 링크(아티팩트)판을 저장소·다운로드·클립보드가 막힌 sandbox iframe에서 검수
npm run build:artifact            # 웹 링크(아티팩트)용 판 dist/KOREA1960_artifact.html
npm run package                   # dist/KOREA1960_v2.2.0.zip (전체 소스 + 단일 HTML)
npm start                         # 개발 서버
```

Node 20 이상(검증: Node 22.23.4), Python 3(검증: 3.13.18). npm 의존성이 없어 `npm install`이 필요 없습니다(`package-lock.json`은 빈 의존성 트리). 브라우저 검수에만 Playwright, 글꼴 재생성에만 fontTools가 필요합니다.
