# 클로드 단계별 작업 지시

한 대화의 처리량이 부족할 때 순서대로 사용한다. 단계 종료 시 CHECKPOINT.md에 현재 파일·엔진 변경·데이터 버전·검증 결과·미완성 항목을 적는다. 사용자가 다음 단계만 입력해도 실제 파일에서 이어서 작업한다.

## 1. 패키지 인수와 실행

첨부 패키지를 읽고 `node tests/engine.test.mjs`를 실행해라. `PLAYABLE_SAMPLE.html` 또는 `python3 tools/serve.py`로 실제 화면을 확인해라. 계산·저장·데이터 구조를 설명하는 간단한 인수 메모를 남기고 원본 파일을 보존한 상태에서 개선 브랜치를 시작해라. 이 단계에서 게임을 다른 장르로 다시 만들지 않는다.

## 2. 핵심 UI 완성

상황판과 사건, 권한 단계, 비용·지연 효과, 지지도, 법안 단계, 건설 큐, 예산 수입/지출 설명을 다듬어라. 제공 이미지를 연결하고 데스크톱/모바일 실제 화면을 검사해라. 같은 게임 상태를 공유하고, 잠금·비활성 사유를 명확히 표시해라. 스크린샷만 있는 목업이 아니라 입력 가능한 게임이어야 한다.

## 3. 캠페인·분기 강화

역사 앵커와 조건부 사건의 맥락을 검토하고 현재 경로에 맞는 문장을 렌더링해라. 시드·가상 선거·의회·사업·지연 효과·엔딩까지 240턴 자동 진행을 검사한다. 데이터에 없는 실제 사건을 추가하려면 기관 출처를 확인하고, 검증되지 않으면 가상 사건으로 분류해라.

## 4. 완성도와 접근성

초보자용 월별 안내, 지표 툴팁, 거래 취소/확인 흐름, 키보드 접근, 차트 설명, 읽기 쉬운 대비, 작은 화면, 저장 실패 시 안내를 구현해라. 저장 파일은 실행 코드나 임의 HTML을 포함하지 못하며 잘못된 ID·수치·버전을 거부해야 한다.

## 5. 납품·검수

테스트와 실제 화면 검수를 실행한 결과를 QA_REPORT.md에 적고 전체 소스 ZIP과 단일 실행 HTML을 만든다. 새로 구현한 기능, 아직 설계만 있는 기능, 알려진 제한을 분리해라. 사용자의 시작 흐름인 압축 해제→HTML 열기→새 게임→사건 선택→월 종료→저장/재개를 직접 확인해라.

## 다시 이어서 작업할 때 붙일 문장

“첨부된 현재 프로젝트와 CHECKPOINT.md를 먼저 읽고, 실제 파일의 상태를 기준으로 이어서 개발해. 이미 완료된 구현은 보존하고 남은 단계의 첫 작업부터 시작해. 설명만 하지 말고 실행 가능한 파일을 수정하고 검증 결과를 제출해.”
