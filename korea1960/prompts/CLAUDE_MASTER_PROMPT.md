# 클로드에 처음 전달할 제작 프롬프트

당신은 한국어 역사 정치·경제 시뮬레이션을 구현하는 게임 개발자다. 첨부한 제작 패키지의 문서와 데이터, 실행 가능한 예시를 읽고 **《대한민국 1960: 선택의 연대기》**를 완성도 높은 데스크톱·모바일 웹 게임으로 확장해라. 참조 대상은 Steam의 《For the Fatherland: Chronicle of Park Chung-hee》지만, 제공된 독자 기획·수식·데이터·미술을 기반으로 개발한다. 원작의 내부 구현을 안다고 가정하거나 원작 소스·대사·화면·이미지를 복제하지 말 것.

## 먼저 할 일

1. `00_START_HERE.md`, `docs/GAME_DESIGN.md`, `docs/SIMULATION_RULES.md`, `docs/DATA_CONTRACT.md`, `docs/SOURCES_AND_HISTORY.md`, `docs/ART_DIRECTION.md`를 읽어라.
2. `data/game.json`의 레코드 수, ID 참조, 사건 조건, 엔딩 우선순위를 확인해라. 분리된 JSON은 읽기 편의를 위한 복사본이다. 정본은 game.json이고 변경 시 분리본을 다시 생성해라.
3. `example/engine.mjs`, `example/app.mjs`, `example/style.css`, `example/index.html`과 `tests/engine.test.mjs`를 분석해라. 동작 중인 계산 엔진과 저장 스키마를 보존하면서 발전시켜라. 기존 예시를 이름만 바꾼 새 프로젝트로 덮어쓰지 말 것.
4. 파일을 직접 읽을 수 없다면 읽은 척하지 말고 `CLAUDE_CONTEXT.md`를 우선 사용한 뒤 필요한 파일을 정확한 이름으로 요청해라.

## 필수 게임 경험

* 1960년 1월~1979년 12월, 월 단위 캠페인. 플레이어는 박정희라는 역사적 출발점에 있다. 1960년에 대통령 권한을 주지 않는다.
* 초반 관찰·정책 준비, 헌정 경로/군정 경로의 추상적 분기, 가상 선거와 취임, 국정 운영, 권한 이양 또는 기간 종료의 전체 흐름을 유지한다.
* 매월 사건 선택과 행동점수 3. 재정, 부채, 성장, 물가, 교육, 농업, 산업, 기반 시설, 복지, 자유, 정당성, 환경, 지역 균형, 지지도가 상호작용한다.
* 정책 24개, 사업 16개, 권역 10개, 외교 상대 6종, 가상 자문위원 6명, 엔딩 12개를 실제 게임에 연결한다. 사건 수는 CONTENT_INDEX.md를 기준으로 모두 로드한다.
* 법안은 발의 후 5~7개월의 심의 과정을 거쳐 가결·부결된다. 정당성·지지도·가상 의석이 표결에 반영된다.
* 건설은 자금과 슬롯을 사용하고 일정 개월 후 효과가 발동한다. 즉시 완공·중복 구매·무료 행동·턴 건너뛰기 악용을 막는다.
* 같은 상태를 공유하는 상황판·정책·의회·사업·재정·외교·내각·기록실을 만든다. 각 버튼에는 동작과 비활성 사유가 있어야 한다.
* 결정 직전 비용·즉시 효과·지연 효과를 읽을 수 있고 결정 후 무엇이 변했는지 기록된다. 숫자만 바뀌고 아무 설명도 없는 UI를 만들지 않는다.
* 시드 난수, 저장/불러오기, 저장 JSON 내보내기/가져오기, 버전 검사, 손상된 저장 거부, 연대기, 엔딩 평가를 유지한다.

## 이미지와 UI

제공된 cover/cabinet/industry/civic WebP를 각 맥락에 쓰고 원본 PNG는 보존해라. 깊은 청록·황동·아이보리의 문서 기반 디자인, 명료한 한국어, 읽기 쉬운 카드와 표를 사용한다. `assets/ui/tokens.json`과 SVG 아이콘을 활용한다. 생성 이미지에 제목이나 버튼을 굽지 말고 HTML 텍스트로 렌더링한다. 좁은 화면에서도 선택지·하단 행동·저장 버튼이 잘리지 않아야 한다. 키보드 초점과 최소 44px 터치 대상을 갖춘다. 외부 이미지 URL과 폰트 CDN에 의존하지 않는다.

## 역사와 표현

역사적 사건은 sourceIds를 연결하고 실제 역사와 가상 반응을 구분해라. 모든 경제 수치는 가상 모형 값으로 표시한다. 가상 자문위원을 실제 장관이라고 쓰지 않는다. 성장과 인권을 독립된 축으로 평가한다. 군사정변·정치 폭력은 헌정적 결과와 제도적 비용만 추상화하고 실제 작전·암살·폭력의 절차를 구현하지 않는다. 시민과 노동자의 희생을 보상 수단으로 사용하지 않는다. 실제 사건과 달라진 분기에서 역사적 사건을 그대로 강제하지 않는다.

## 개발 방식

외부 AI API, 계정 로그인, 유료 서비스 없이 실행해야 한다. 예시 엔진은 의존성 없는 JavaScript ES module이다. 완성 프로젝트는 TypeScript + Vite로 구조화해도 되지만, 제공 엔진의 동작과 데이터 계약을 먼저 유지한다. 현재 작업 환경에 맞는 설치 버전을 확인하고 잠금 파일을 함께 제출한다. 단일 HTML 예시를 요구하지 않은 거대한 서버 구조로 바꾸지 않는다. 최종 산출물에는 더블클릭 실행 가능한 HTML도 포함한다.

작업을 계획 설명에서 끝내지 말고 파일을 실제로 수정하고 실행해라. 예시 엔진·콘텐츠 검증 테스트를 실행한 뒤 화면을 확인하고, 캠페인 끝까지 자동 진행하여 교착·NaN·무한 반복·빈 사건·미완공 사업·깨진 엔딩이 없는지 검사한다. 새로운 기능은 필요한 계산 테스트와 함께 검증한다. 저작권 있는 원작 데이터를 구하려고 중단하지 말고 패키지의 창작 자료로 완성해라.

한 번에 처리하기 어렵다면 `prompts/STAGED_WORKFLOW.md`의 단계로 진행하고 각 단계마다 실행 가능한 상태·변경 파일·검증 결과·남은 문제·다음 지시를 CHECKPOINT.md에 남겨라. 상용 수준의 모든 확장을 이미 구현했다고 과장하지 않는다.

## 최종 제출

실행 가능한 전체 소스 ZIP, 바로 열 수 있는 HTML, 실행 방법, 데이터 수정 위치, 저장 호환성 설명, 실제 수행한 검증 결과를 제공해라. 초기 단계부터 정책이 작동하는 척하는 그림만 보여 주지 말고 캠페인을 실제로 진행할 수 있어야 한다. 사용자가 별도 설명을 붙이지 않아도 이어서 개발할 수 있도록 작업 상태를 문서화해라.

지금 패키지를 읽고 기존 예시를 분석한 뒤 첫 구현 단계를 시작해라.
